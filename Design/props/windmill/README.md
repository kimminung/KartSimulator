# 풍차 원본·애니메이션 전달 준비

2026-10-14 · 사용자 사용 확정 · 로컬 커밋·공유 준비 완료

사용자가 지정한 RetireX 개발 RP에서 풍차의 모델·애니메이션·텍스처와 연결 JSON을 `source/`에 바이트 동일하게 복사했다. 운영자 원본은 수정하지 않았다. 앱용 GLB·USDZ 변환과 실제 씬 배치는 테크 후속 작업이다.

| 파일 | 역할 |
| --- | --- |
| `windmill.geo.json` | `geometry.windmill`, 6개 본·89개 큐브 |
| `windmill.animation.json` | 큰 날개와 뒤쪽 보조 날개의 연속 회전 |
| `windmill.png` | 갈색 목재 외형, 512×512 |
| `windmill_small.png` | 흰색·녹색 외형, 512×512. 작은 지오메트리가 아니라 같은 모델의 도색 변형 |
| `windmill.json` | 원래 모델·텍스처·애니메이션 연결과 스케일 |
| `windmill.render_controllers.json` | q.variant 0/1의 텍스처 선택 |

본 구조는 `root → tower → cap` 아래 `shaft → sails`, `fantail`이다. 모델의 피벗과 본 이름을 유지한다.

## 회전과 단위

- `sails`: 원본 Z축 `q.life_time × 36°`, 한 바퀴 **10초**.
- `fantail`: 원본 X축 `q.life_time × −50°`, 한 바퀴 **7.2초**.
- 샤프트의 기본 X 회전 **−8°**와 피벗을 보존한다. 큰 날개의 애니메이션 축은 이 부모 자세를 따른다.
- 모델은 Bedrock 유닛이며 16유닛 = 1 m다. 원래 client entity에는 `scale = 2`가 있다. 앱용 변환 단위와 씬 배율은 분리해 기록한다. 원본 2배를 자동으로 굽지 않는다.
- Molang은 RealityKit에서 실행되지 않으므로 테크가 해당 각속도를 런타임 회전 또는 애니메이션 키프레임으로 옮긴다. 0°→360° 두 쿼터니언만 넣으면 같은 자세로 취급될 수 있어 중간 회전을 포함해야 한다.
- 각 본을 독립 반복시키거나 누적 시간으로 구동한다. 두 회전을 하나의 정확한 반복 클립으로 굽는다면 공통 주기는 180초다.
- 축·부호는 원본 Bedrock 기준이다. glTF/USDZ 좌표계 변환 후 실제 회전 방향과 샤프트 기울기를 확인한다.

## 제안 배치와 확인 기준

루키 오벌의 잔디 공원 외곽에 작은 풍경 소품으로 우선 배치하는 것을 제안한다. 노면·가드레일·주행 카메라 시야와 겹치지 않게 한다. 배치는 디자인 사용 승인과 별개로 테크가 씬 규모에 맞춘다.

확인 기준: 6개 본·89개 큐브·UV·두 도색 유지, 큰 날개 10초·보조 날개 7.2초 회전, 루프 이음새 없음, 디오라마와 3인칭에서 주행 방해 없음. JSON 연결·개수·본 이름은 확인했으나 변환 모델 렌더와 앱의 애니메이션 동작은 아직 확인하지 않았다.
