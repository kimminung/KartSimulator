# 속도계 레이어 전달본

2026-10-14 · 디자인 · 결정 63 · 사용자 승인·공유 준비 완료

사용자가 지정한 바탕화면 `RXO/UI/속도계_및_게이지/`의 PSD와 내보낸 PNG를 기준으로 정리했다. 마인크래프트용 통합 프레임 시트에서 복원하지 않았다. 사용자 원본을 그대로 복사했으며 새로 그릴 부분은 없다.

## 파일과 쌓는 순서

모든 레이어는 **103×79 RGBA**다. 같은 크기·원점으로 겹친다. 투명 여백을 잘라내거나 레이어마다 가운데를 다시 맞추지 않는다.

| 순서 | 전달 파일 | 사용자 원본 | 역할 |
| --- | --- | --- | --- |
| 1 | `speedometer_background.png` | `hud_frame_back.png` | 원형 바탕과 뒤쪽 패널 |
| 2 | `speedometer_gauge.png` | `hud_boost_fill.png` | 게이지 색. 각도 마스크로 연속 채움 |
| 3 | `speedometer_frame.png` | `hud_frame_front.png` | 일반 앞 프레임과 km/h |
| 3 대체 | `speedometer_frame_boost.png` | `hud_frame_front_boost.png` | 부스트 앞 프레임과 km/h |
| 4 | 앱의 숫자 텍스트 | 시스템 고정폭 숫자 | 가운데 실제 속도 |

위 PNG 4개는 원본과 바이트 동일하다. 일반·부스트에 같은 게이지 레이어를 사용한다. `hud_km.png`의 빨간 사각형은 숫자 배치 가이드이므로 표시하지 않는다. `hud.png`의 999도 예시이므로 앱 에셋으로 쓰지 않는다. PSD·PNG 원본 사본은 `source/`에 보관한다.

## 연속 게이지 명세

- `ratio = clamp(abs(speedKmh) / 20, 0, 1)`.
- 중앙 `(51.5, 52)`, 시작 각도 약 **172.875°**, 시계 방향 총 **194.25°**. 화면 좌표에서 오른쪽이 0°, 아래가 90°다. 왼쪽 아래에서 위쪽을 지나 오른쪽 아래로 채운다.
- `endAngle = startAngle + sweepAngle × ratio`인 부채꼴로 게이지를 마스킹한다. 0에서는 게이지를 숨기고 1에서는 전체 지정 각도를 보인다.
- `speedometer_gauge_mask.svg`는 100% 부채꼴의 참고용 마스크다. 실제 앱은 같은 중심·각도로 매 프레임 연속 마스크를 만든다. 51장 또는 102장 프레임을 다시 만들 필요가 없다.
- 원본 게이지에는 아래쪽까지 색이 있으므로 전체 PNG를 아무 마스크 없이 올리지 않는다. 위 지정 각도만 사용해야 원래 계기판과 맞는다.
- 숫자 영역은 `(x:23, y:31, width:55, height:25)`. 실제 숫자는 가운데 정렬·시스템 고정폭 숫자. `km/h`는 프레임에 이미 들어 있다.
- 속도에 표시 배율을 곱하지 않는다. 기본 최고 속도 4.0 m/s = 14.4 km/h는 눈금의 72%다. 내리막 보너스 18 km/h도 0~20 범위 안이다.
- 부스트 프레임은 반올림한 숫자가 아니라 실제 속도와 `0.9 × maxSpeed × 3.6`을 비교한다. 기본값은 **12.96 km/h**다. 튜닝 최고 속도가 바뀌면 이 기준도 함께 바뀐다.
- 픽셀 이미지 확대에는 nearest-neighbor를 쓴다. 여기서 이미지 배율과 속도 표시 배율은 별개다.

정확한 값은 `dial_spec.json`에 있다. 원본 통합 시트의 비어 있는 일반·부스트 프레임과 원본 레이어 합성을 비교했고, 두 경우 모두 RGBA 픽셀이 일치했다. 최대로 찬 프레임은 연속 각도 마스크 방식의 가장자리 래스터 차이가 있을 수 있다.

## 미리보기와 재생성

`preview.png`는 4개 레이어와 0·7.2·12.96·14.4·18·20 km/h 합성 예시다. `preview-empty-*`·`preview-full-*`은 숫자 없는 합성이다. 숫자와 폰트는 배치 예시이며 실제 SwiftUI 화면 검수 결과는 아니다.

```powershell
node Design/hud/build.mjs
```

Node.js와 sharp를 사용한다. PSD·원본 PNG는 수정하지 않는다. `validation.json`에 크기·알파·원본 동일 여부·부스트 기준을 기록한다.

## 현재 상태

레이어 정리와 합성 미리보기까지 준비했고 사용자가 공유 준비를 요청했다. 직접 분리하거나 새로 그릴 일은 없다. 앱 코드·번들 리소스는 테크 소유라 바꾸지 않았다. 테크는 이 레이어와 명세를 HUD에 연결하고 visionOS·iPhone·iPad에서 가독성을 확인해야 한다. 원격 게시와 앱 적용은 후속이다.
