# 성능·출시 예산 측정 (M6 — Issue #45·#46, 결정 59)

2026-10-12, 테크. 실기기(Apple Vision Pro) 프레임 측정은 **아직 비어 있다** — 아래 "실기기 측정 절차"대로 사용자가 Instruments를 돌려 표를 채운다. 코드 쪽 예산 항목(엔티티·삼각형·번들·메모리 추정)은 이 Mac에서 계산했다.

## 3. 메모리 추정

- 텍스처: 카트 1종 활성(기본+발광 2장, ≤ 2048²) + 서킷 노면은 단색 재질(텍스처 없음) → 수십 MB 수준.
- 오디오: 엔진음 5개 WAV 상주(≈ 1 MB) + 배경음 1곡 스트리밍(`AVAudioPlayer`).
- 실기기에서 Xcode Memory Report로 디오라마/3인칭 각각 1분 주행 후 값을 아래 표에 적는다.

## 4. 실기기 측정 절차 (사용자)

1. Xcode에서 실기기 연결 → Product ▸ Profile → **RealityKit Trace** 템플릿.
2. 각 모드에서 **리본 루프** 3랩(루프 포함)을 돌며 기록: 디오라마 / 3인칭.
3. 아래 표를 채운다. 기준: 90 fps(11.1 ms) 유지, 프레임 드롭 < 1 %.

| 장면 | 평균 프레임 시간 | 최악 프레임 | 드로우콜 | 메모리(피크) | 비고 |
| --- | --- | --- | --- | --- | --- |
| 디오라마 · 첫 바퀴 | | | | | |

프레임이 떨어지면 순서대로: ① 미니맵 라벨 텍스트 메시 수 줄이기 ② 서킷 USDZ 재질 13 → 6으로 합치기(`build_circuit.py` PALETTE) ③ 3인칭에서 소품(나무·가로등·바위) 숨기기.

## 5. 콘솔 로그

- `DEBUG-*` 로그는 전부 `debugLog()`(Utilities/DebugLog.swift)로 바꿨다 — Release에서는 컴파일되지 않는다.
- "Modifying state during view update": HUD가 attachment로 바뀐 뒤(결정 25·26) 시뮬레이터 콘솔에서 더 이상 확인되지 않았다. 실기기에서 재현되면 폴링 루프를 `Task.sleep` 대신 `DisplayLink`로 옮긴다.
