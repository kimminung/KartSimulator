# 핀치 카트 — 디자인 PRD (Windows·Blockbench)

Oct 10, 2026 · @Coulson

## 1. 문서 전제

이 PRD는 요구상세서 12장의 "기본 제안"을 채택한 상태에서 디자이너가 Windows PC와 Blockbench로 만들 모든 것을 정의한다. 디자이너는 [KartSimulator](https://github.com/kimminung/KartSimulator.git) 레포의 `design` 브랜치에서 작업하고, 테크 PRD와 같은 이름(파일명·그룹명·HUD 필드명·효과음 이름)을 쓴다.

| 채택한 결정 | 디자인에 미치는 영향 |
| --- | --- |
| 공간 유형 (a) 볼륨 테이블탑 — 트랙 전체가 1.4×1.1m 볼륨 안 미니어처로 보임 | 카트·타일은 위에서 내려다볼 때 예쁘게. 지붕·보닛 윗면 디테일이 중요하고 바닥면은 보이지 않음 |
| 카트 길이 1.5m(월드) → 볼륨에서 6cm | 작은 크기에서도 읽히는 큰 색 면, 가는 선 금지 |
| 트랙은 복셀 타일 4종 조합, 타일 4m(월드) → 16cm | 타일 이음새가 어느 방향으로 붙어도 맞아야 함 |
| 미니맵은 볼륨 우측 하단 월드 고정, 테이블 지름 24cm | 미니맵은 Diorama 테이블 모양을 유지하고 색만 우리 팔레트로 |
| ~~전진 2단계(절반·최대), 후진 없음~~ → **양손 핀치 거리 = 연속 페달**(모을수록 전진, 약 40cm 중립, 벌릴수록 후진), 한 손 핀치 = 회전(속도 유지) — 테크 결정 30·31 | 핀치 상태 HUD는 "정지·중립·전진·후진·좌·우" 6상태 + 페달 게이지 |
| 3랩 타임어택, 효과음 + 엔진음 + **배경음 3곡**(결정 55, 10장) | 랩·타임이 HUD의 주인공. 배경음은 −20 LUFS로 효과음 아래에 깐다 |
| 앱 이름 **"핀치 로버" / "Pinch Rover" 확정**(결정 53, Issue #30. 가칭 "핀치 카트"는 쓰지 않음) | 14장에서 이름 후보 3개를 제안하고 결정 기록에 남김 |
| 운전 모드 **디오라마 + 3인칭 2종**(1인칭은 멀미로 폐기, 결정 47). 3인칭 카메라는 카트 진행 방향 기준 | 조작법 그림·HUD는 손 핀치 한 가지 조작만 그린다 |

**테크 PRD와 공유하는 이름**: 카트 피벗 `A`(앞왼)·`C`(앞오)·`B`(뒤왼)·`D`(뒤오)·`steering_wheel`·`root`(4장 4-0, 결정 47. 초판의 `body`·`wheel_fl` 등은 쓰지 않음) · 타일 `straight`, `curve`, `start`, `grass` · HUD 필드 `lap`, `totalLaps`, `lapTime`, `totalTime`, `speedKmh`, `drive`, `left`, `right` · 효과음 `countdownTick`, `go`, `checkpoint`, `lapComplete`, `finish`, `wallBump`, `respawn`.

## 2. 디자인 목표와 원칙

목표는 "책상 위에 놓인 복셀 장난감 트랙"처럼 보이면서, 6cm 크기의 카트와 1m 거리의 HUD가 한눈에 읽히는 것이다.

| 원칙 | 뜻 | 적용 예 |
| --- | --- | --- |
| 큰 면, 적은 색 | 한 에셋에 색 6개 이하, 1픽셀 디테일 금지 | 카트 보닛은 단색 + 2픽셀 줄무늬 하나 |
| 위에서 본 실루엣 | 테이블탑이라 사용자는 45° 위에서 본다. 윗면과 측면 상단이 얼굴 | 바퀴는 몸체보다 어두운 색으로 윤곽 분리 |
| 트랙은 배경, 카트는 주인공 | 트랙 채도를 카트보다 낮게 | 트랙 회색·잔디 녹색은 채도 40% 이하, 카트는 70% 이상 |
| HUD는 숫자 먼저 | 랩·타임이 가장 크고, 장식은 없음 | 숫자 고정폭, 라벨은 작은 대문자 |
| 상태는 색 + 모양 | 색만으로 구분하지 않음 | 핀치 상태 아이콘은 손 모양 + 화살표 + 색 |
| 픽셀 룩은 3D에만 | UI 글꼴은 가독성 우선 | 제목만 픽셀 폰트, 본문·숫자는 시스템 폰트 |
| 한 번 보면 아는 조작 | 온보딩 그림 5장으로 설명 끝 | 글 없이 손 그림만으로 이해 가능해야 함 |

## 4. 카트 명세

**4-0. 완성형 카트 5종의 피벗과 움직임 (2026-10-11, 결정 47 — 이 절이 우선)**

카트는 RetireX에서 온 완성형 USDZ 5종이다(결정 14). 아래 "Blockbench 1종" 사양은 초판 기록으로만 남긴다. 5종에는 RetireX 원본(`RP/models/entity/<id>.json`)의 피벗이 공통으로 있고, 움직임은 RetireX `physics` 애니메이션 식을 그대로 옮긴다(Issue #26).

| 피벗 | 뜻 | 움직임 |
| --- | --- | --- |
| `A` / `C` | 앞왼 / 앞오 바퀴 (Bedrock: +x = 왼쪽, −z = 앞) | X축 굴림(각속도 = 속도 / 바퀴 반지름) + Y축 조향 최대 30° |
| `B` / `D` | 뒤왼 / 뒤오 바퀴 | X축 굴림 |
| `steering_wheel` | 핸들 | Z축 최대 82°, **핀치 연동**(왼손만 핀치 = 왼쪽) |
| `root` | 차체 | 회전 시 바깥쪽 roll 최대 4°(속도 비례), 가감속 pitch 1~2°(선택) |

- 조향·핸들 평활은 RetireX와 같은 `lerp(dt × 14)`(약 0.07 s), 차체 기울기는 `lerp(dt × 10)`.
- 회전 중심은 bone pivot이 아니라 **바퀴 메시 바운딩 박스 중심**을 쓴다. bogubkart `D` pivot x 부호 오류, arcrix·bogubkart 바퀴 pivot과 메시 중심의 y 차이(1.3·0.85유닛)가 원본에 있다.
- 접지는 모델 최저점이 아니라 **바퀴(`A`~`D`) 바닥**, 높이는 **노면 윗면(타일 바닥 + 0.25 m)** 기준(Issue #23).

**4-0b. 운전자 캐릭터 (2026-10-11, 결정 47 — 결정 14의 "해당 없음"을 뒤집음)**

- 간단한 블록 캐릭터 1종 `driver_01`. 앉은 자세, 그룹 `body`·`head`·`arm_l`·`arm_r`·`leg_l`·`leg_r`, 색은 스타일 가이드 팔레트, 마인크래프트 스킨·텍스처 금지(결정 21).
- **카트 원본과 같은 Bedrock 유닛**으로 만들고, 카트 5종 위에 각각 올려 엉덩이 기준점을 맞춘 **좌석 표**(`Design/karts/seats.md`)를 낸다. 시작값은 RetireX `minecraft:rideable` 좌석 위치.
- 파일: `Assets/blockbench/driver/driver_01.bbmodel` → `Assets/export/glb/driver_01.glb`. 테크는 카트 엔티티의 자식으로 붙여 카트 배율을 그대로 받게 한다(Issue #29).
- 완료 기준: 엉덩이가 좌석 면과 실제 크기 기준 ±1 cm, 다리가 차체를 뚫지 않음.

**(초판) Blockbench 1종 카트 사양 — 결정 14로 대체됨**


카트 1종을 Blockbench 'Generic Model' 프로젝트로 만들고, 16유닛 = 1m 기준으로 길이 24유닛(1.5m)에 맞춘다. 바퀴 4개는 별도 그룹으로 분리하고 원점을 바퀴 중심에 두어 앱이 회전시킬 수 있게 한다.

**Blockbench 프로젝트 설정**

| 항목 | 값 |
| --- | --- |
| 포맷 | Generic Model (Java Block/Item 아님 — 큐브 회전 각도 제한을 피하기 위해) |
| 단위 | 16유닛 = 1m. 모델은 유닛 단위로 모델링, 내보낼 때 glTF 옵션에서 1/16 배율 적용 |
| 텍스처 | 1장, 128×128 PNG, 알파 없음. UV는 픽셀 격자에 정렬 |
| 정면 | 북쪽(-Z). Blockbench 뷰포트의 'North' 표시 방향이 카트 앞 |
| 원점 | 모델 바닥 중앙 = (0, 0, 0). 바퀴 바닥이 Y=0에 닿음 |

**치수 (유닛 / m)**

| 부위 | 치수 |
| --- | --- |
| 전장 × 전폭 × 전고 | 24 × 16 × 13 유닛 (1.5 × 1.0 × 0.81 m) |
| 바퀴 지름 × 폭 | 6 × 4 유닛. 앞뒤 바퀴 중심 간격 16유닛, 좌우 14유닛 |
| 몸체 바닥 높이 | 2유닛 (지면과 틈) |
| 운전석 | 선택. 넣는다면 단순 블록 캐릭터, 높이 8유닛 이내 |

**그룹 구조 (이름 그대로 사용)**

```markdown
kart_01            (루트, 원점 0,0,0)
├─ body           몸체·범퍼·시트·스포일러
├─ wheel_fl       원점 = 바퀴 중심 (앞 왼쪽)
├─ wheel_fr
├─ wheel_rl
├─ wheel_rr
└─ driver         선택
```

- 그룹 이름은 영문 소문자 + 밑줄만. 큐브 이름은 자유지만 한글·공백 금지.
- 바퀴는 몸체와 큐브를 공유하지 않는다(겹치는 큐브 금지). 앱이 바퀴를 X축으로 돌릴 때 몸체를 뚫지 않을 여유 1유닛.
- 좌우 대칭 부품은 미러 UV를 쓰지 않고 각각 UV를 할당한다(일부 변환기에서 미러 UV가 깨짐).

**색 사용**: 몸체 `kart-red`, 포인트 `kart-cream`, 바퀴 `wheel-dark` + `wheel-rim`. 색은 최대 6개.

**내보내기 (`File > Export > Export glTF`)**

| 옵션 | 값 |
| --- | --- |
| 형식 | Binary `.glb` (텍스처 포함) |
| 배율 | 1/16 (유닛 → m). 옵션이 없는 버전은 그대로 내보내고 테크가 Blender에서 0.0625배 적용 |
| 애니메이션 | 포함 안 함 (바퀴 회전은 코드) |
| 파일명 | `kart_01.glb` → `Assets/export/glb/`. 원본 `kart_01.bbmodel` + `kart_01.png` → `Assets/blockbench/kart/` |

**셀프 체크**: 내보낸 `.glb`를 Windows 3D 뷰어 또는 Blockbench에서 다시 열어 (1) 그룹 6개 이름, (2) 바운딩 박스 1.5×1.0×0.81, (3) 텍스처 뭉개짐 없음, (4) 정면이 -Z인지 확인한 뒤 커밋한다.

## 5. 트랙 타일 세트

타일은 4m×4m(64×64유닛) 정사각 4종이며, 어느 회전으로 붙여도 노면·연석·벽이 이어지도록 모든 연결부를 타일 변의 정확히 가운데에 둔다. 트랙은 테크 쪽 스크립트가 이 타일을 격자에 놓아 만든다.

| 타일 | 입구 → 출구 (회전 0일 때) | 내용 |
| --- | --- | --- |
| `straight` | 남(+Z) → 북(-Z) | 직선 노면, 양쪽 연석, 양쪽 벽 |
| `curve` | 남(+Z) → 동(+X) | 90° 커브. 노면 중심선은 타일 중심을 지나는 1/4 원호. 바깥쪽 벽만, 안쪽은 연석 |
| `start` | 남 → 북 | `straight`와 같되 타일 중앙에 폭 전체를 가로지르는 체커 출발선(2유닛 칸) |
| `grass` | 없음 | 잔디 바닥 한 장. 트랙이 안 지나는 칸을 채움. 높이 0 |

**단면 규격 (유닛)**

| 요소 | 치수 | 색 |
| --- | --- | --- |
| 타일 | 64 × 64, 바닥 두께 2 | `grass` 또는 `dirt` |
| 노면 | 폭 48 (3.0m), 두께 2, 타일 변 가운데에서 ±24 | `road`, 가장자리에 1유닛 `road-line` |
| 연석 | 노면 양옆 각 4유닛, 높이 1 | `curb-red`/`road-line` 4유닛 간격 교대 |
| 벽 | 연석 바깥 4유닛, 높이 8(0.5m), 두께 2 | `wall` (울타리 기둥 패턴) |
| 여백 | 벽 바깥 ~ 타일 경계 2유닛 | `grass` |

**연결 규칙**

- 노면 중심은 항상 타일 변의 가운데(32유닛)를 지난다. 그래야 `rot` 0·90·180·270 어느 조합에도 이음새가 맞는다.
- 커브의 바깥 벽은 타일 모서리를 따라 ㄱ자로 돌고, 직선 타일의 벽 끝과 같은 위치(연석 바깥 4유닛)에서 끝난다.
- 타일끼리 겹치는 큐브 금지. 타일 경계에 딱 맞춰 끝낸다(틈 0).
- 각 타일은 Blockbench 프로젝트 1개, 원점은 타일 바닥 중앙, 텍스처는 `tiles.png` 1장을 4종이 공유(128×128).

**파일**: `Assets/blockbench/tiles/tile_straight.bbmodel` 등 4개 + `tiles.png` → 내보내기 `Assets/export/glb/tile_straight.glb` 등. 2×2로 임시 배치한 스크린샷을 `Design/reference/tiles_preview.png`로 첨부해 이음새를 보여 준다.

## 6. 미니맵 외형

## 7. HUD 레이아웃

HUD는 볼륨 안에서 트랙 뒤쪽 위에 떠 있는 가로 패널 하나(랩·타임)와, 트랙 앞쪽 양 모서리의 작은 요소 둘(왼쪽 아래 핀치 상태, 오른쪽 아래 미니맵)로 구성한다. 트랙 중앙과 카트 주변에는 아무것도 올리지 않는다.

랩·타임 패널은 트랙 뒤쪽 가장자리 위 공중에, 핀치 상태와 미니맵은 앞쪽 두 모서리의 트랙 위 0.10 m에 떠 있어 트랙 어느 칸이 노면이어도 가리지 않는다.

**요소 규격 (볼륨 1.4 × 0.6 × 1.1 m 기준)**

| 요소 | 위치 | 크기 | 내용 (테크 PRD `RaceHUDState` 필드) |
| --- | --- | --- | --- |
| 랩·타임 패널 | 트랙 뒤쪽 가장자리 위, 높이 0.42m, 사용자를 향해 15° 기울임 | 0.56 × 0.10 m | `lap`/`totalLaps`(28pt), `lapTime`(34pt), `totalTime`(22pt), `bestLapTime`(17pt) |
| 속도 | 랩·타임 패널 오른쪽 끝 | 0.12 × 0.10 m | `speedKmh` 정수 + "km/h"(22pt) |
| 핀치 상태 | 볼륨 앞 왼쪽 모서리 안쪽 (x −0.55, z +0.40), 트랙 위 0.10m에 떠 있음 | 0.18 × 0.08 m | 왼손·오른손 아이콘(`left`/`right`), 가운데 동작 아이콘(`drive`) |
| 미니맵 | 볼륨 앞 오른쪽 모서리 안쪽 (x +0.50, z +0.35), 트랙 위 0.10m에 떠 있음 | 지름 0.24 m | 6장 |
| 손 안내 배너 | 랩·타임 패널 바로 아래 | 0.40 × 0.06 m | "양손이 보이게 해 주세요" — `left.tracked` 또는 `right.tracked`가 false일 때만 |
| 카운트다운 | 트랙 중앙 위 0.30m 높이, 사용자 방향 | 숫자 높이 0.12 m | `phase == countdown(n)`. 3·2·1 후 "GO". 주행 시작 0.5초 후 사라짐 |
| 복귀 표시 | 카트 위 0.06m | 0.08 × 0.03 m | `respawning` 동안 "복귀 중" |

**핀치 상태 HUD 6상태 (2026-10-11 개정, 테크 결정 30·31의 `DriveState.pedal(Float)` 기준)**

| `drive` | 왼손 | 오른손 | 가운데 아이콘 | 페달 게이지 |
| --- | --- | --- | --- | --- |
| `stopped` | 해제(`ui-ink` 40 %) | 해제(`ui-ink` 40 %) | `stop` ■ | 숨김 |
| `waiting`, `pedal(0)` (중립, 약 40cm ±2cm) | 핀치(`ui-cyan`) | 핀치(`ui-cyan`) | 없음(게이지만) | 가운데 눈금만 |
| `pedal(+v)` 전진 | 핀치 | 핀치 | `arrow_forward` ↑ (`ui-cyan`) | 가운데에서 위로 v만큼, `ui-cyan` |
| `pedal(−v)` 후진 | 핀치 | 핀치 | `arrow_reverse` ↓ (`ui-magenta`) | 가운데에서 아래로 v만큼, `ui-magenta` |
| `turnLeft` | 핀치 | 해제 | `arrow_left` ↰ | 숨김 |
| `turnRight` | 해제 | 핀치 | `arrow_right` ↱ | 숨김 |

- **페달 게이지**: 가운데 아이콘 오른쪽의 세로 막대(폭 16pt, 높이 84pt — 600×480 목업 기준). 가운데 가로 눈금이 중립이고, 위쪽 절반은 전진, 아래쪽 절반은 후진 세기다. `abs(pedal)`(0~1)만큼 채운다. 전진·후진은 색(`ui-cyan`/`ui-magenta`), 방향(위/아래), 화살표 모양 세 가지로 구분한다(2장 "상태는 색 + 모양" 원칙).
- 게이지 아래 글자: "전진 70 %", "후진 40 %", "중립" (17pt, `ui-ink` 80 %).
- 예전 `arrow_forward_full` 아이콘(2단계 전진)은 없앴다.

**속도계 (2026-10-11, 결정 47, Issue #28)**

- 속도 표시는 `km/h` 글자 대신 **계기판**으로 한다. RetireX 계기판 `rxo_hud_dial.png`(1133×790, 일반·부스트 두 벌 프레임 시트)를 디자이너가 `Design/hud/`로 정리해 넘긴다: 바탕 `speedometer_frame.png`, 게이지 채움, 부스트용 `speedometer_frame_boost.png`.
- 게이지 칸 = `speedKmh / 20`. 눈금은 **0~20 km/h**(최고 속도 4.0 m/s = 14.4 km/h가 약 72 % 지점), **표시 배율은 두지 않는다**(랩 타임·트랙 길이와 감각을 맞춤). 최고 속도의 **90 % 이상**에서 부스트 프레임(`speedometer_frame_boost.png`)으로 바꿔 체감을 준다. 가운데 숫자는 `monospacedDigit` 정수 + "km/h"(결정 55, Issue #28 테크 제안 수용).
- 모드 전환 버튼은 1인칭 폐기로 2개(디오라마·3인칭)다(결정 47).

패널 배경은 visionOS 글래스 재질(`.regularMaterial`)에 모서리 반경 12pt, 내부 여백 12pt. 글자는 `hud-ink`, 강조는 `accent-blue`. 모든 숫자는 고정폭(`monospacedDigit`)으로 흔들림을 막는다.

- 디오라마를 열면 메뉴 창이 박스를 가리지 않아야 한다: 메뉴 창은 박스 **위쪽**에 있고, 박스는 창 아래·앞에 놓인다(창을 옮기기 어려우면 박스 위치를 바꾼다).
- 3인칭(실제 크기 트랙)에 들어가면 메뉴 창은 **트랙 밖으로** 빠진다(숨김 가능). 주행을 끝내면 메뉴 창을 **사용자 정면**으로 다시 부른다. 종료 수단은 HUD의 "박스 닫기"다.

**전환 규칙**

- 메뉴 윈도우는 볼륨이 열려도 닫히지 않고 뒤쪽으로 물러난다. 주행 중에는 내용이 "일시정지" 버튼 하나로 바뀐다.

- 결과 화면은 완주 1초 뒤에 뜨고, 그동안 볼륨에는 완주 연출(10장)이 나온다.
- 일시정지 중 볼륨은 70% 밝기로 어두워지고 HUD 숫자는 멈춘다.

## 9. 조작 온보딩

조작법은 글 없이도 이해되는 그림으로 끝내고, 각 그림에는 손 모양(또는 머리 방향)·움직임 화살표·결과(카트 방향)를 한 장에 담는다. 같은 그림을 조작법 화면, HUD 핀치 상태 아이콘, 앱 스토어 스크린샷에 재사용한다. 2026-10-12 4차 개정(결정 55): **1인칭 폐기**(결정 47), **3인칭은 디오라마와 완전히 같은 규칙(후진 포함)**으로 확정(테크 결정 49, Issue #24). 조작 그림은 디오라마 5장 한 벌을 두 모드가 같이 쓴다. 아래 1인칭·3인칭 표는 기록용이고, 그 그림 파일(`gesture_fp_*`, `gesture_tp_*`)은 지웠다. 2차 개정(결정 40): 운전 모드가 디오라마·1인칭·3인칭 세 가지가 되어(테크 결정 39) 조작법 화면은 모드 세그먼트로 나뉘고, 그림은 모드별로 따로 둔다 — 디오라마 5장, 1인칭 2장, 3인칭 4장.

**디오라마** (박스를 밖에서 보며 조종. 양손 핀치를 시작한 자리에 두면 전진, 핀치한 채로 벌리면 후진)

| 번호 | 그림 | 손 | 화살표 | 카트 | 한 줄 설명 (20자 이내) |
| --- | --- | --- | --- | --- | --- |
| 1 | 전진 | 양손 핀치, 보통 간격 그대로 | 두 핀치 점을 잇는 `ui-cyan` 점선("자리 유지") | 앞으로 ↑ | 양손을 핀치한 채로 있으면 전진 |
| 2 | 후진 | 양손 핀치, 어깨너비보다 넓게 벌린 상태 | 양손 바깥쪽 ← → (`ui-magenta`) | 뒤로 ↓ | 핀치한 채로 양손을 벌리면 후진 |
| 3 | 좌회전 | 왼손만 핀치, 오른손 펼침 | 없음 | 왼쪽으로 ↰ | 오른손을 떼면(왼손만 핀치) 좌회전 |
| 4 | 우회전 | 오른손만 핀치, 왼손 펼침 | 없음 | 오른쪽으로 ↱ | 왼손을 떼면(오른손만 핀치) 우회전 |
| 5 | 정지 | 양손 펼침 | 없음 | 정지 ■ | 양손을 떼면 멈춤 |

- 전진/후진은 핀치를 시작한 순간의 손 간격이 기준이다(절대 40 cm 피벗이 아니라 상대 드래그, 테크 결정 39). 핀치를 시작한 자리 그대로(시작 간격 + 4 cm 안)이면 **전진 최대**이고, 그보다 벌리면 후진이 세진다(코드 `dioramaPedalValue`, 앱 안내 "그 자리에 두면 전진, 벌리면 후진"). 중립 구간은 없다. (결정 47에서 "시작한 자리 = 중립"이라는 이전 문장을 정정.) 회전 중에는 속도가 유지되므로, 달리다 한 손을 떼면 그 속도로 돈다.

## 11. 멀미·편안함 배려

테이블탑 방식이라 시점이 움직이지 않아 멀미 위험은 낮지만, 작은 카트를 오래 응시하는 눈 피로와 양팔을 벌린 채 유지하는 팔 피로가 남는다. 디자인은 이 둘을 줄이는 방향으로 정한다.

| 항목 | 지침 |
| --- | --- |
| 시점 (디오라마) | 박스 안 어떤 것도 사용자 머리를 따라 움직이지 않는다. HUD도 월드 고정 |
| 시점 (3인칭, 결정 47) | 카메라 기준은 **카트 진행 방향**이다. 기준 방향은 모드에 들어온 순간의 정면으로 고정하고, 고개는 ±45° 안에서 자유롭게 돌려 양옆을 볼 수 있다(아무것도 따라오지 않음). ±60°를 2초 넘게 유지하면 기준을 천천히 다시 맞춘다. 코너 뒤 세계 회전은 평활(2.5/s, 어지러우면 1.5). 머리 방향은 조향에 쓰지 않는다 |
| 1인칭 | 폐기(결정 47). 머리 방향 조향과 실제 크기 시점이 겹쳐 멀미가 컸다 |
| 카트 크기 | 6cm가 너무 작으면 디자인에서 키우지 말고 테크 PRD 배율(0.04)을 올리자고 결정 기록에 제안 |
| 깜빡임 | 0.2초보다 빠른 점멸 금지. 체크포인트 전환도 1회 전환으로 끝냄 |
| 대비 | HUD 글자 대비 4.5:1 이상. 글래스 배경 위 `hud-ink` 사용 |
| 팔 피로 | 전진 거리 기준(0.22m·0.40m)은 팔꿈치를 몸에 붙인 채 손만 벌려도 닿는 값. 온보딩 그림도 팔을 크게 벌리지 않은 자세로 그린다 |
| 세션 길이 | 3랩 25~30초 × 3 = 1분 30초 내외. 결과 화면에 "잠깐 쉬어가세요" 같은 문구는 넣지 않는다(짧은 세션) |
| 앉기 권장 | 첫 실행 조작법 화면 하단에 "앉아서 플레이하면 편해요" 한 줄 |
| 소리 | 효과음 7개 모두 −12 dBFS, 날카로운 고음 금지. 배경음은 −20 LUFS로 효과음·엔진음 아래(결정 55) |

**규칙**

- 파일명 변경 금지. 이름을 바꾸면 테크 쪽 스크립트와 RCP 씬이 깨진다. 바꿔야 하면 Issue로 먼저 합의.
- 한 커밋에는 관련 파일을 함께 넣는다(`.bbmodel` + `.png` + `.glb`). 메시지 예: `kart_01: 스포일러 추가, 바퀴 색 wheel-dark로`.
- `.glb`, `.png`, `.wav`는 Git LFS 추적 대상(`.gitattributes`는 테크가 만들어 둠). LFS 설치 후 `git lfs install` 1회.
- 내보낸 뒤 4장 셀프 체크를 거친 것만 올린다.

**리뷰 요청·확인 흐름**

1. `design` 브랜치에 커밋 → `main`으로 PR. 제목 `[design] kart_01 v2`, 본문에 바뀐 점 3줄과 Blockbench 스크린샷 1장.
2. 테크가 변환해 `Assets/review/kart_01_<날짜>.png`(위·정면 렌더)를 `Dev`에 커밋하고 PR에 링크를 단다.
3. 디자이너는 렌더를 보고 색·비율·이음새를 확인한다. 고칠 것이 있으면 같은 PR에 커밋 추가, 없으면 "OK" 코멘트.
4. 테크가 머지. 실기기 캡처는 마일스톤마다 `Assets/review/device_<날짜>.png`로 공유.

- `App/`, `Tracks/`, `Assets/export/usdz/`는 수정하지 않는다. 문제는 Issue로 남긴다.
- 파일명·그룹명·`type`·`RaceEvent` 이름은 PRD 1장 표를 따르고 바꾸지 않는다.
- 팔레트에 없는 색을 쓰려면 먼저 `Design/style-guide.md`에 추가하고 PR 본문에 이유를 쓴다.
- Blockbench 조작은 사람이 한다. Claude는 `.bbmodel`(JSON) 검사, 문서·SVG·목업 작성, 커밋 메시지·PR 본문 작성을 맡는다.

## 14. 디자이너 Claude(Windows) 작업 가이드

Windows에서는 Xcode·Reality Composer Pro·실기기를 쓸 수 없으므로, 디자이너의 Claude는 Blockbench 결과물을 검사하고 문서·벡터·목업을 만드는 역할을 맡는다. 3D 모델링 자체는 사람이 Blockbench에서 한다.

**할 수 있는 일**

| 일 | 방법 |
| --- | --- |
| `.bbmodel` 검사 | `.bbmodel`은 JSON이다. 그룹 이름 6개, 원점 좌표, 큐브 겹침, 텍스처 크기 128×128, 색 수 ≤ 6을 스크립트로 검사 |
| 텍스처 팔레트 검사 | PNG의 색을 추출해 3장 팔레트 밖의 색을 보고 |
| 아이콘·온보딩 그림 | SVG를 직접 작성 (24×24 격자, 240×240) |
| HUD·메뉴 목업 | HTML/SVG로 레이아웃을 그리고 PNG로 저장 |
| 문서 | `Design/style-guide.md`, PR 본문, Issue, 결정 제안 작성 |
| 효과음 | CC0 소스 검색·정리, `LICENSES.md` 작성. 간단한 칩튠 톤은 Python으로 생성 가능 |
| 앱 이름 제안 | 15장 열린 질문에 후보 3개와 이유 |

**할 수 없는 일 (테크에게 요청)**

- USDZ 변환·확인, Reality Composer Pro 씬 편집, 실기기 캡처
- 트랙 JSON 생성(스크립트는 테크 소유). 트랙 모양에 대한 요청은 Issue로
- 앱 코드 수정

**프롬프트 예시**

```markdown
Assets/blockbench/kart/kart_01.bbmodel을 열어 Docs/design-prd.md 4장 기준으로 검사해 주세요:
그룹 이름 6개, 원점이 바닥 중앙인지, 바퀴 원점이 바퀴 중심인지, 큐브가 겹치는지,
텍스처가 128×128이고 색이 6개 이하인지. 문제가 있으면 수정 방법을 Blockbench 조작 순서로 적어 주세요.
```

```markdown
Docs/design-prd.md 9장 규격대로 gesture_01_forward.svg ~ gesture_05_stop.svg 5장을 만들어
Design/onboarding/에 저장해 주세요. 손은 1인칭 시점, 핀치 지점은 accent-blue 원으로 강조합니다.
```
